# ブラウザ内翻訳の追加高速化

2026-11-10。PLaMoをブラウザ内で使う条件を保ち、短文の処理、待機順、通信、描画、モデルの準備を変更した。今回は速度の反復比較を省き、影響範囲のテストと短い実機スモークで確認した。

## まとめる処理と待機中の要求

短いラベルは最大8件、合計640文字、推定160トークン以内でまとめる。先頭の文章、見出し、改行や文末句点を含む入力、リンクなどで分かれた断片は対象外とした。モデルへ渡した番号、行数、空行、数値を検査し、一つでも対応しなければ全件を個別に訳し直す。部分的に正しそうな行だけを採用しない。一括訳を単独入力のキャッシュキーへ保存することも避けた。[batch.ts](../../features/translate/batch.ts)。

同じ組の一部の原文が削除された場合は、生存する要素の結果だけを表示する。全件が不要になれば要求を取り消す。通常の要求も原文の変更・削除時にrequest単位で取り消す。タブとsessionの名前空間を維持し、他の要求を誤って取り消さない。[content.ts](../../features/translate/content.ts)、[background.ts](../../features/translate/background.ts)。

送信済みの待機要求はスクロール後に表示距離を更新する。選択翻訳を先にし、その中で15秒以上待った要求を救済し、通常は画面に近い要求から選ぶ。入力長を揃える処理は距離と待機時間の優先帯を越えない。同文の推論を共有する場合は、生存する利用先の最小距離を使う。[scheduler.ts](../../features/translate/scheduler.ts)、[engine.ts](../../features/translate/engine.ts)。

## 通信と描画

最初の途中出力は全文を送信し、以後は60msの制限を保ちながら増えた部分だけを送る。生成中の文章が置き換わった場合は全文へ戻す。受信側はUTF-16のoffsetを検査し、欠落や重複した差分を誤接続しない。最終応答の全文で確定する。

最初の訳文はすぐに表示し、続く更新は同じフレームで最新の文字列へまとめる。最終結果はフレームを待たずに表示する。DOMの再走査もまとめるが、非表示タブではフレーム停止を待たずに原文の追加・変更・取消を処理する。

## モデルを先に準備する

設定画面の「モデルを準備」で、読込とウォームアップを翻訳開始前に済ませられる。設定画面を開くだけではダウンロードしない。実行方法、機能の有効状態、保存済みモデルとの一致をbackgroundで検証する。翻訳と準備は同じschedulerを使い、モデルの切替が進行中の推論に重ならないようにした。

CPUでは共通プロンプトのKVを再利用する。GPUのKV再利用は従来どおり無効とし、状態のRAM保存と通常checkpointも無効のままとした。CPUスレッド数は論理コア数の半分、最大8。GPUは従来の最大4スレッドである。CPUでの速度差は未測定である。

## 2Bと0.8Bによる投機的デコード

モデル欄に「2B＋0.8B補助（実験）」を追加した。GPU上で0.8Bが最大4トークンを提案し、2Bが検証する。主モデルを0.8Bへ変更する方式ではない。実験用の方式は1要求・4096トークンで実行し、メモリと状態管理の範囲を抑える。利用できない場合は通常のGPU 2B、次にCPU 2Bへ戻す。既定の0.8Bは変更していない。

SDKはdraftを通常モデルの分割ファイルと混ぜず、独立した`draft.gguf`としてWASMへ渡す。固定nativeはdraftのパスだけを設定しても方式が有効にならなかったため、`0006-enable-draft-speculation.patch`でDRAFT_SIMPLEを設定する。通常版と互換版のWASMを再ビルドし、全4パッチと成果物のhashを記録した。[runtime adapter](../../scripts/translation-runtime.ts)、[nativeパッチ](../../scripts/wllama/patches/0006-enable-draft-speculation.patch)。

短いChromeスモークでは、最初の文で提案8トークン中5トークン、取消後の次の文で8中6トークンが採用された。要求の取消と、その後の新しい文の生成も成功した。3件のラベル一括翻訳では件数・日本語出力・バージョン番号3の保持を確認した。[スモーク記録](translation-additional-smoke.json)。通信経路のスモーク1回では15件の原文を13要求で処理し、3件を一括で翻訳した。差分配信も確認した。これらは動作の確認であり、高速化率や長文での品質の証明ではない。

## 確認範囲と未実施

一括翻訳の形式不一致時の復旧、個別取消、距離更新、aging、差分offset、非表示タブ、準備処理、モデル読込の失敗時の復旧を関連テストで確認した。追加の変更について長時間ベンチマークは実施していない。

一括翻訳は入力の文脈を変える。番号や数値が一致しても意味の対応を保証できるわけではなく、ページごとの品質評価は残る。投機的デコードも追加メモリを使い、採用率や端末によって遅くなる可能性がある。長文のSWA巻戻し、別GPU、互換WASMでの実機確認は省略した。

前回改善しなかったGPU4枠・先読み8段落・別量子化は既定へ入れていない。追加学習や別ランタイムへのPLaMo移植、本文・訳文の永続保存も今回の実装に含めない。

既存資料にはOllamaの権限と導入を未実装として扱う記述と、SakuttoのSWAコメントの枠数が実装と異なる記述が残る。詳細は[調査レポート](translation-further-performance.md)にまとめた。今回の実装では現行コードとREADMEに従った。
