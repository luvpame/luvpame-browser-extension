## Question

確定した機能群を、共通メニューと機能別設定でどう操作するか。

### 決める点

- 機能を切り替える単位、初期値、設定を変えた際の開いているタブへの反映。
- 共通メニュー内のコピー操作、設定画面への入口、キーボード操作と結果表示。
- TextareaVim の URL 別設定など、既存の個別設定を残す方法。
- 統合した機能の対象サイトと権限要求の関係。全サイトで動く機能を無効にした際の期待する動作。
- 旧拡張の保存済み設定や LGTM テンプレートを移す必要性と方法。統合後に自動で引き継がれるとは仮定しない。

### 解決条件

共通メニュー、切替単位、設定の初期値、保存済みデータの移行方針をユーザーと合意する。

## 解決記録 — 2026-09-18

ユーザーが提示した5項目の推奨案に「ok」と回答し、以下を合意した。
機能範囲は[統合後に残す機能と重複の扱いを決める](01-feature-scope.md)に従い、Gemini切替は含めない。

### 切替単位と初期値

以下の12機能を個別にON/OFFでき、初期値はすべてONとする。

| 分類         | 個別に切り替える機能                                         |
| ------------ | ------------------------------------------------------------ |
| 共通         | URLコピー、本文コピー、TextareaVim                           |
| GitHub       | LGTM、表挿入、PRコピー、HTMLプレビュー、Devin系リンク        |
| Notion       | ページ内本文コピーボタン、タイトルホバー操作、見出しマーカー |
| Devin Review | マージボタン非表示                                           |

Notionのページ内本文コピーボタンのOFFは、共通メニューの本文コピーを無効にしない。
共通メニューの本文コピーは、Notionでは専用変換、それ以外では汎用変換を使う。

### 共通メニュー、キーボード操作、結果表示

- 共通メニューの項目は「URLをMarkdownでコピー」「本文をMarkdownでコピー」「設定」の3つ。
- メニュー内にコピー結果を表示し、失敗時は理由を表示する。OFFの操作は無効表示にする。
- TabとEnterで操作できるようにする。
- URLコピーの既存ショートカットを維持する。元設定の推奨キーは通常 `Ctrl+Shift+Y`、macOSは `Command+Shift+Y`。
- ショートカット実行時は通知とバッジで結果を知らせる。

### 設定変更の反映、OFF、権限

- 開いているタブにも再読み込みなしで設定変更を反映する。
- Vim編集中にOFFにした場合は、編集内容を元の入力欄へ保存して終了する。
- OFFは該当機能の動作停止を意味する。サイトへのアクセス権限は自動解除しない。
- Vimは全サイトを対象にし、既存のURL許可・除外設定で有効範囲を絞れる形を維持する。ブラウザが拡張の実行を制限するページへの対応を追加する合意ではない。

### 個別設定と保存範囲

- 設定画面にLGTMテンプレートとVimのURL設定を残す。
- テンプレートとURL設定は既存どおりブラウザの同期ストレージへ保存する。
- 12機能のON/OFFはブラウザごとに保存する。

### 旧拡張からの移行

- 必要なLGTMテンプレートとVimのURL設定は、旧設定画面から手動でコピーする。
- 旧拡張のON/OFFは統合拡張の設定画面で指定し直す。
- 自動移行機能は作らない。旧拡張の保存済みデータは今回変更しない。

具体的なManifest権限、対象ブラウザ、設定キー、OFF時のUI復元、機能共存の実現方法は「一つの拡張として動かす内部構成を決める」で扱う。
移行手順の検証と旧拡張の停止・復旧手順は「移行完了の確認方法と元repoの削除条件を決める」で扱う。
今回の変更は計画文書のみ。統合実装、公開、元repo削除は行っていない。
