# Linearデスクトップ版の通信不要なGuide翻訳

アプリ本体を変更せず、DevToolsから起動します。モデルと推論エンジンをファイルから読み込み、Linearの画面内のワーカーでPLaMoを実行します。Ollamaへの接続や外部への本文送信はありません。

## 確認済みの範囲

Linear実機ではWASMとBlobワーカー内のWASM実行を確認しました。モデル推論は、同じ種類のCSP制限を設定した専用Chromeページで、既存の2Bモデルを使って確認しました。CPU版の実際のLinear内での動作はユーザーが確認済みです。GPU対応版は、AppleのMetalアダプターを使う専用Chromeページで、0.8BモデルのGPU割り当て・翻訳・2並列実行を確認しました。GPU対応版も、ユーザーが実際のLinearで動作したことを確認しています。

## この環境で試す

1. `dist/linear-offline/launcher.js` の内容をコピーし、LinearのDevTools Consoleで実行します。
2. Linear既存の下部バーのファイル選択で、`dist/linear-offline/linear-offline.js` と `dist/linear-offline/model.gguf` の2つを選択します。
3. モデル準備後、Guideの英語説明文が自動で日本語に置き換わります。後から追加された説明文と、画面内遷移にも対応します。

この環境の `model.gguf` は、ブラウザ版の既定と同じPLaMo 3 Translate 0.8B（Q4_K_M、573,126,848バイト）です。取得元はブラウザ版のエンジンが使うHugging FaceのモデルURLで、SHA-256 `70891ec70dc7ab4205745a38307867c2881b99239f20327927633abfe4bc9ec6` を照合しています。以前使ったOllamaの2Bモデルは変更せず、`model-2b.gguf` から参照できます。別の環境では、ご自身のPLaMo 3 Translate GGUFを選んでください。

ファイル選択でフォルダが見つからない場合は、`Cmd+Shift+G` を押してリポジトリ内の `dist/linear-offline` の絶対パスを入力します。

実行ファイル・モデル選択、翻訳状態、停止操作は、Linearの「Agent」「履歴」がある既存の下部バーの左側空き領域に入れています。新しいバーは追加せず、Linearの表示領域や既存バーの高さも変更しません。

翻訳中に新しい起動スクリプトを実行した場合は、モデルを読み込み直さず、既存のUIだけをLinearの既存バーへ移動します。以前追加した別バーと表示領域を34px縮めるCSSも、その際に取り除きます。初めて起動するときはファイル選択から始まります。

## 停止と再起動

既存バー内の「翻訳を停止」を押すか、Consoleで `await luvpameLinearOfflineGuide?.stop()` を実行します。原文を復元し、ワーカーとモデルを終了します。モデル読み込み中の停止では、読み込み結果が返った後にそのモデルを終了します。

初回に選んだ実行ファイルとモデルは専用IndexedDBへ保存します。次回は起動コードを実行すると、保存済みのファイルから復元できます。ファイル選択をやり直す必要はありません。起動コードの実行も省く完全自動復元には、[Mac用補助ツールの初期設定](linear-auto-start.md)が必要です。保存データを削除した場合は、初回のファイル選択をやり直します。

## ビルド

`bun run build:linear-offline` で実行ファイルを生成します。ビルドは、既存のネイティブ成果物とSDKのバージョン・ハッシュを検証してから、通常版・互換版の実行コードとWASMを埋め込みます。SDK本来の能力判定で通常版を優先し、必要な環境だけ互換版を使います。生成物は実行本体の `linear-offline.js`、起動用の `launcher.js`、既存翻訳を終了して初期設定を始める `setup.js`、Mac補助用の `restore.js` です。いずれも `dist/linear-offline` に出力します。起動用ソースは `scripts/linear-offline/launcher.ts` です。

モデルファイルは配布物に含めません。生成ディレクトリはGit管理の対象外です。既存のChrome拡張の実行方法や設定を変更せず、別のビルドとして生成します。

## 制限

WebGPUを優先します。ブラウザ版と同じくGPUへのモデル割り当てを試み、実際にGPUへ配置されたログを確認できた場合だけステータスバーに「GPU」と表示します。GPUではコンテキスト8192、2並列を利用します。CPUはコンテキスト4096、1並列です。CPUスレッド数はブラウザ版と同じ指定ですが、クロスオリジン分離がない環境ではSDKにより単一スレッドになります。

GPUが使えない場合はCPUへ切り替わり、「CPU・GPU利用不可」と明示します。同じ文章は、同じモデルを読み込んでいる間だけ既存の翻訳キャッシュで再利用します。Ollamaのネイティブ実行と同一の実行エンジンではありません。大きいモデルでは読み込み中もメモリを使用します。

Guideの見出し、ボタン、コード差分は翻訳しません。モデルがPLaMo 3 Translateでなければエラーにします。現時点の試作は通常の日本語訳だけを対象にしています。

既存バーの配置はクライアントの `data-agent-toolbar-bounds` 属性を使って特定します。見つからない場合は、別のバーを追加せずエラーにします。Linear側でこのDOM構造が変わった場合は追従が必要です。

## 状態表示

未選択・モデル準備中・Guide待機・翻訳中・翻訳完了を区別します。翻訳中は完了・処理中・待機中の件数、失敗がある場合は失敗件数も表示します。件数は段落数ではなく、翻訳要求に含まれるテキスト数です。リンクの前後などで分割される場合や、一括要求内の各テキストも含みます。

状態表示にマウスを重ねると、モデル名・デバイス・件数の定義・最新のエラー詳細を確認できます。ボタンはモデル未選択時に「閉じる」、準備中に「準備を中止」、準備後に「翻訳を停止」と表示します。「翻訳を停止」は原文を復元し、モデルも終了します。

状態集計など実行中の処理ロジックを更新する場合は、一度 `await luvpameLinearOfflineGuide?.stop()` で終了してから、更新した起動コードと実行ファイル・モデルを読み込み直します。レイアウトだけの変更は、モデルを維持したまま反映できます。
